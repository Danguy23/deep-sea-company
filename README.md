# deep-sea-company

Generated by [Rojo](https://github.com/rojo-rbx/rojo) 7.7.0.

## Getting started

Build the place with:

```bash
rojo build -o "deep-sea-company.rbxlx"
```

Open the authored salvage place in Roblox Studio, run `rojo serve`, connect the
Rojo plugin, sync, and Play with Output open. The hand-built scene must contain
`Workspace.Submarine.SafeZone`, `Workspace.GreyboxRuin.ThreatBounds`, and Parts
tagged `Loot` with numeric `Value` attributes.

## Current playtest

### Run loop and HUD

1. Filter Output for `[Run]`. With a living player, expect
   `Lobby -> Dive | dive 1; banked 0 / 200` after the configured lobby delay.
2. Confirm the HUD contains HP, stamina, quota, and four inventory slots. It must
   not contain an air bar or light control. Pressing F has no gameplay effect.
3. Pick up loot with E and return it to `SafeZone`; entering the zone still banks
   carried loot. Reaching quota must produce `Dive -> Return -> Payout`, followed
   by the next Dive with the raised quota.
4. Let the creature down the only player before quota is met. Expect `[Down]`,
   then `Dive -> Return | all players downed`, failed Payout, GameOver, and a reset
   to Lobby. After respawn, the next Dive should start normally.

### Threat sight

The creature uses `Config.Threat.SightRange` and
`Config.Threat.FieldOfViewAngle`. Detection requires the player to be within both
the range and view cone and for a Workspace raycast from the creature to reach the
character without hitting geometry first.

1. Filter Output for `[Threat]`. Expect the service-ready log to show the current
   sight range and field of view, then an idle spawn log at Dive start.
2. Stand in front of the creature with an unobstructed view. Within 100 studs and
   the default 120-degree cone, expect `Idle -> chase` even though no player light
   exists.
3. Put a solid wall between the creature and player. Expect `Target lost` and a
   return to patrol. Remaining nearby but behind the wall must not reacquire.
4. Step back into its view and verify chase, delayed sprint, and contact downing
   still work. The creature must not change color or gain a highlight based on
   player lighting.

### SafeZone navigation and scene warnings

During Dive, the teal home marker points toward `SafeZone` while the living player
is outside it. It hides inside the sub, outside Dive, on death, or when the zone is
missing. `SafeZone` remains the loot deposit point only.

Temporarily rename `SafeZone` before Play. Loot and threat systems should warn
loudly, no creature should spawn, and the navigation marker should stay hidden.
Restore the expected scene name before continuing.

## Configuration

All tunables live in `src/shared/Config.luau`. Important threat controls are
`SightRange` and `FieldOfViewAngle`. Loot placement samples random ground points
throughout `GreyboxRuin.ThreatBounds`; padding, SafeZone distance, attempts, and
minimum separation are configurable.

All persistent game logic lives under `src/`. Studio or MCP should only be used
for the physical scene and playtesting.
